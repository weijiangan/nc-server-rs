# Phase 15 — Edge security hardening

Task tracking for [`SPECS/03-implementation-plan/plan/15-edge-security-hardening.md`](../03-implementation-plan/plan/15-edge-security-hardening.md) — the security reassessment of the PHP-FPM forwarding path. Waves 1-3 + the parity corpus; status via checkboxes only.

## Wave 0 — Decision spikes

- [x] **0.1 Session resolution: direct store read vs. hardened round-trip — DECIDED 2026-08-10 (feasible, NOT worth it — hardened round-trip).** Evidence: session files are encrypted (`encrypted_session_data|s:N:"cipher|iv|hmac|3"`, plaintext = JSON), the `oc_sessionPassphrase` cookie is the plaintext passphrase, decryption needs a phpseclib-exact port. Decided against: it serves only browser requests (sync = app tokens unaffected), pins an undocumented PHP runtime format (crypto exactness = silent wrong identity), and requires a shared session path in split topologies. F3 → negative caching + concurrency cap; revocation → cache-TTL knob.
- [x] **0.2 Verify PHP-FPM `$_COOKIE` population — DECIDED 2026-08-10.** FPM DOES populate `$_COOKIE` (probe dumped `["probe"=>"1","session"=>"sess123"]`); the shim's manual parse is redundant — keep as defense-in-depth, correct the comment.

## Wave 1 — Production gate

- [x] **1.1 Static file serving (F1) — DONE 2026-08-10.** Superseded by the Phase 18.1 `try_static_files` whitelist (`/core /dist /themes /apps` + `robots.txt` + `index.html`), which is strictly stronger than the proposed deny list and 404s before the fs stat. Live-verified: all F1 paths → 404. Resolution note in the plan.
- [x] **1.1 remainder: pin the security property — DONE 2026-08-10.** Whitelist deny-path unit tests (`static_denies_data_directory`, `static_denies_dotfile_path`, `static_denies_3rdparty`, `static_denied_prefix_case_insensitive` + traversal + positive control), a live probe in the parity gate (`difftest smoke`: `/data/.ocdata`, `/.htaccess`, `/3rdparty/*` → 404 on both SUT and oracle), and the `docs/deployment.md` nginx deny-rules operator guidance (the canonical layer's version of the same rule).
- [x] **1.2 Trusted proxies and client identity (F2) — DONE 2026-08-10.** Port PHP's `getRemoteAddress`/`getServerProtocol`/`getInsecureServerHost` line-for-line (`client_identity.rs` — manual v4/v6 CIDR masking, no `ipnet` dep); `trusted_domains` enforcement for native routes mirroring `lib/base.php:872-912`; `ConnectInfo` wiring; consumers (throttle key, proxy `REMOTE_ADDR`, SameSite `is_https`) switch to the resolved identity; 24 unit tests + live A/B verification (spoofed XFF ignored, trusted-proxy XFF honored, untrusted Host → exact 400 body) + diff-test 20/20.

## Wave 2 — Resource governance

- [x] **2.1 Session-resolution exhaustion (F3) — DONE 2026-08-10.** Negative caching (5 s TTL, `SESSION_NEGATIVE_CACHE_TTL`) of failed `__session_resolve` under the same SHA-256 cookie key — junk-cookie bursts hit memory, not FPM; concurrency semaphore on `FastCgiState` (`session_resolve_concurrency` config key, default 8 ≈ `pm.max_children / 2`, bounded 1 s wait then anonymous); the positive cache TTL became a per-request revocation knob (`session_cache_ttl` config key, default 60 s); rotation note documented (remember-me tokens rotate at most once per TTL window). **Per-IP rate limit NOT added — the plan's own criterion ("skip if negative caching + semaphore prove sufficient under load") is met by construction; skip documented, not speculative throttle-key semantics.** Tests: `negative_result_cached_within_ttl`, `negative_cache_expires_after_ttl`, `positive_and_negative_entries_share_eviction`, `session_cache_positive_ttl_is_a_knob`.
- [ ] **2.2 Body limits with correct status (F4) — PARTIAL: 413 part done 2026-08-10, semaphore DEFERRED.** `to_bytes` overflow now returns 413 (Payload Too Large, parity: nginx/Apache) via `LengthLimitError` source detection; the comment/code mismatch is fixed. **In-flight body semaphore deferred**: bounds RSS only under concurrent abuse from untrusted clients — defensive theater for the target deployment (LAN/private); revisit if the box is ever exposed. No 503+`Retry-After` path exists yet.
- [ ] **2.3 Response-body deadline (F5) — DEFERRED 2026-08-10.** The header phase already carries `fastcgi_timeout_ms`; the residual gap (FPM hangs mid-body → client hangs) is low-frequency on the target deployment. The wrong "transport enforces it" comment at the old `lib.rs:128-130` was removed in passing (the doc now lists 413 and the header-phase 504 only). Revisit with a per-chunk idle deadline on `CgiBodyStream` (60 s, `fastcgi_timeout_ms`-adjacent config) when hung-worker incidents appear.
- [x] **2.4 CGI header accumulator cap (F8, partial) — DONE 2026-08-10.** 64 KiB cap while scanning for `\r\n\r\n`; overflow → 502 + `warn!`. Containment for a misbehaving app (legit blocks are < 1 KiB).

## Wave 3 — Trust-boundary hygiene

- [x] **3.1 Marker guarantee explicit (F7) — DONE 2026-08-10.** `x-nc-proxied` added to the strip list (the trust marker is inject-only); header forwarding extracted into the pure `build_fcgi_params` (headers in → `HTTP_*` params out, no I/O); regression tests pinning no client input can set `HTTP_X_NC_*` (`no_client_input_can_set_http_x_nc` incl. case permutations, `ordinary_headers_forward_and_identity_headers_are_stripped`, `content_headers_are_not_forwarded_as_http_params`).
- [ ] **3.2 URI normalization at the proxy boundary (F6) — DEFERRED 2026-08-10.** Real only when nc-server sits directly on the internet without nginx normalization in front (nginx normalizes `$uri` before the proxy); the canonical deployment keeps nginx. Revisit with the 404-reject at `derive_script_info` if a direct-exposure deployment appears.
- [ ] **3.3 Hop-by-hop header hygiene (F8, remainder) — DEFERRED 2026-08-10.** Residual exposure is `transfer-encoding`-class smuggling through hyper's existing header handling; low likelihood behind the canonical proxy. Revisit with a strip list on the forwarded `HTTP_*` params.
